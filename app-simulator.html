v0.0.13-alpha roadmap
DONE Speed test (WiFi + USB)
TODO Real camera streaming to PC
TODO PC receiver display window
TODO Pro subscription (Google Play)
DONE PC Control from app (start/stop) — now also called automatically before streaming, not just from Settings buttons
DONE Zero-touch connect: USB now auto-forwards on plug-in (PC-side watcher, no adb/python command), Wi-Fi auto-discovers + auto-starts PC services — Install_PhoneCam.vbs is the only manual step, once, and it's completely silent (no console ever)
DONE Fixed receiver crash-loop: services were launched as bare scripts instead of `-m pc_receiver.x`, so receiver.py died on import on every single start — invisible since output went to devnull. Now module-launched, single bind + per-connection error isolation, logs to file
DONE Fixed cmd window flashing on repeat: CREATE_NO_WINDOW alone didn't stop adb.exe from popping a console under the hidden pythonw.exe parent — needed DETACHED_PROCESS + stdin redirection too. Also removed a stale pre-VBS Startup shortcut that pointed at a visible-console .bat
DONE PC service now gated on OBS: PhoneCam_Service.vbs is a lightweight WMI watcher (no ports, no processes) that only starts control_server.py while obs64.exe/obs32.exe is actually running, and stops the whole tree when OBS closes — was previously "always on from login"
DONE Real H.264 encoding replaces per-frame JPEG: H264Encoder.kt (MediaCodec, buffer-mode) on the phone, PyAV-backed h264_decoder.py on the PC. Video bitrate setting now actually configures the encoder. Not yet verified on real camera hardware — no device in this sandbox — but PC-side decode has real encode/decode round-trip tests
DONE Fixed the real reason OBS got nothing on record: adb reverse failing once (a race right after USB authorization, confirmed in the wild) marked that device as "handled" forever, so the tunnel just never came up for the rest of the session. Now retries every poll cycle until it actually succeeds. Also hardened CameraStreamer against a H264Encoder construction failure silently killing frame delivery
DONE Fixed viewfinder looking like a cheap pixelation filter at low resolutions (e.g. 360p): PreviewView defaulted to "performance" mode (SurfaceView/hardware-overlay scaling, blocky at large upscale factors on some GPUs) — switched to "compatible" mode (TextureView, proper GPU bilinear filtering), so a real low-res capture now looks like real low-res video, not a mosaic effect. The preview genuinely captures at the chosen resolution either way, that part was never fake
DONE Fixed "PC not reachable" over USB: adb reverse silently fails outright ("more than one device/emulator") the moment a phone shows up twice in `adb devices` — which happens for a single phone with USB connected AND wireless debugging paired at the same time. Now every reverse call targets a specific device via -s instead of hoping only one is attached
DONE Found the real reason no video ever reached the PC: the YUV->Bitmap conversion feeding both encoders bulk-copied camera planes assuming zero row padding, which real camera HALs routinely violate (this code path was never exercised on real hardware before now). A stride mismatch there silently broke every single frame, uncaught, on the analyzer thread — no crash, camera just never showed up. Rewritten stride-aware, matching the approach already used on the encode side
DONE Fixed "Cannot reach PC" over WiFi: Settings' PC-control actions (Start PC, Check, speed test...) fell back to 127.0.0.1 — the phone's own loopback — whenever no IP had been manually discovered first. Now auto-discovers the same way the main streaming flow already did. (PC-side firewall/discovery both checked and confirmed working; if this still fails, the router may have client/AP isolation enabled between WiFi devices — outside what either side of this app can fix)
TODO Real audio capture + transmission — audio bitrate/codec settings are still decorative, only the local level meter is real, nothing is sent to the PC
BLOCKED Native OBS plugin (a real Source inside OBS, not just feeding its Virtual Camera) — backlog idea, not started. Current pyvirtualcam approach already works and is what DroidCam/Iriun do too; revisit only if that stops being enough
